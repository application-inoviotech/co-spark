HOW PRODUCT CONTENT NOW WORKS

The new InsuranceContent resolver uses product CMS overrides first, reviewed
product defaults second, and category copy as the fallback for remaining fields.
Existing deployed products receive corrections without reseeding catalog data.
The product admin adds coverage, options, benefits and FAQ editors. Saving one
product does not change its siblings. Blank fields restore their defaults.
Coverage and FAQ lines require Title | Description / Question | Answer format.
Text remains escaped by Blade when rendered on public pages.

DEPLOYMENT

Changes are in the local working tree; commit and push the intended files before
pulling them on the live server. package-lock.json was already modified before
this task and was not changed as part of the content correction.

After pulling on live, run with the site's PHP version:

    composer dump-autoload
    php artisan migrate --force
    php artisan optimize:clear

The migration adds one nullable JSON content column to insurance_products.
No catalog seeder is needed; reseeding could overwrite existing CMS changes.
No JavaScript source changed. The existing local admin Vite build was generated
to allow the admin HTML regression checks to run.

Then check /insurance/term-life, /insurance/flood, /insurance/medicare,
/insurance/asset-management, /claims and an Insurance products edit form.
The public product corrections cannot be verified on live until deployment.
